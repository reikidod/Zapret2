# Вклад в проект

## Принципы

- Изменения должны решать конкретную задачу и оставаться небольшими.
- Не менять поведение сетевых стратегий без описания причины и проверки.
- Не перезаписывать пользовательские списки, профили и конфигурацию.
- Не добавлять фиктивные статусы, неподтверждённые проверки или декоративные элементы без функции.
- Не включать в репозиторий сторонние бинарники zapret2/WinDivert без ясного происхождения и лицензии.

## Перед изменением

1. Проверьте текущую ветку и последние коммиты.
2. Прочитайте соответствующий раздел [ROADMAP.md](ROADMAP.md).
3. Уточните, какие файлы и пользовательские данные затрагивает изменение.
4. Для сетевых изменений опишите ожидаемую область действия и способ отката.

## Локальная проверка

После переноса исходников в стандартную структуру Cargo используйте:

```powershell
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets
cargo build --release --target x86_64-pc-windows-msvc
```

До этого переноса команды выполняются из каталога исходников, извлечённого из `zapret2-rust-source.zip`. Не отмечайте проверки как пройденные, если они не запускались.

## Оформление изменений

- Один логический набор изменений на commit.
- Сообщение commit должно описывать результат, например: `Fix process shutdown handling`.
- Для исправления укажите шаги воспроизведения и ожидаемое поведение.
- Для UI-изменения приложите скриншоты до/после, если они помогают оценить результат.
- Для сетевых изменений укажите bundle, Windows build, профиль и приложения, на которых выполнена проверка.

## Что приложить к bug report

- Версия приложения и Windows.
- Версия/источник zapret2 bundle.
- Название профиля и описание действия.
- Точный текст ошибки и релевантный фрагмент журнала.
- Шаги воспроизведения и ожидаемый результат.

Перед публикацией удалите из логов IP-адреса, токены, имена пользователей и другие личные данные.
