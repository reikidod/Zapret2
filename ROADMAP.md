# План развития

Документ фиксирует последовательность работ и проверяемые условия завершения. Пункты не считаются реализованными, пока изменение не попало в репозиторий и не прошло указанные проверки.

## Текущее состояние

- [x] Rust + egui GUI и Windows x64 workflow.
- [x] Portable EXE как артефакт GitHub Actions.
- [x] Поиск основных файлов zapret2 bundle.
- [x] Встроенные и пользовательские профили.
- [x] Запуск/остановка winws2 и просмотр журнала.
- [x] Импорт аргументов из BAT/CMD.
- [x] Обновление общих списков с сохранением `*-user.txt`.
- [ ] Автоматический разбор результатов blockcheck2 — пока запускается отдельная консоль.

## Этап 1. Надёжная основа

**Цель:** сделать проект удобным для сопровождения и снизить риск регрессий.

- [ ] Перенести исходники из `zapret2-rust-source.zip` в обычную структуру Cargo в корне репозитория.
- [ ] Проверить, что workflow собирает проект из обычной структуры без распаковки исходного архива.
- [ ] Добавить `cargo fmt --check` и `cargo clippy` в CI.
- [ ] Добавить тесты для разбора аргументов, конфигурации и операций со списками там, где это возможно без Windows runtime.
- [ ] Зафиксировать поддерживаемые версии Windows и формат конфигурации.
- [ ] Проверить обработку ошибок: отсутствующие файлы, неверные пути, занятый процесс, отказ UAC.

**Готово, когда:** чистый checkout собирается в CI; форматирование и статические проверки проходят; базовые тесты выполняются автоматически.

## Этап 2. Управление процессом и диагностика

**Цель:** предсказуемый запуск и остановка стратегий.

- [ ] Проверить жизненный цикл `winws2.exe`: запуск, повторный запуск, остановка, аварийное завершение.
- [ ] Не допускать запуска второго экземпляра без явного решения пользователя.
- [ ] Показывать понятную причину ошибки запуска и код завершения.
- [ ] Разделить сообщения GUI и вывод управляемого процесса.
- [ ] Добавить экспорт диагностического отчёта без секретов и персональных данных.
- [ ] Проверить корректное завершение дочернего процесса при закрытии приложения.

**Готово, когда:** все переходы состояния отображаются в интерфейсе, ошибки воспроизводимы по журналу, зависшие процессы не остаются незаметно.

## Этап 3. Профили и совместимость приложений

**Цель:** дать пользователю контроль над тем, какой трафик обрабатывается.

- [ ] Сделать состав профиля прозрачным: команда, аргументы, списки и используемые файлы.
- [ ] Добавить проверку аргументов до запуска с указанием проблемного параметра.
- [ ] Продумать пользовательские списки доменов/IP и явные исключения.
- [ ] Подготовить проверяемые сценарии совместимости для Steam, Discord, YouTube, Telegram Proxy и Valorant.
- [ ] Не обещать совместимость по названию профиля: показывать, что именно проверялось и в каких условиях.

**Готово, когда:** пользователь может понять область действия профиля до запуска, а изменения не затрагивают приложения вне выбранных правил.

## Этап 4. Проверка стратегий

**Цель:** превратить blockcheck2 из внешнего окна в понятный рабочий процесс.

- [ ] Изучить форматы вывода и варианты поведения blockcheck2 в поддерживаемом bundle.
- [ ] Сохранять исходный лог проверки.
- [ ] Разбирать результаты только для подтверждённых форматов; неизвестный вывод показывать как текст, а не угадывать.
- [ ] Сравнивать результаты проверок и помогать выбрать профиль.
- [ ] Предусмотреть ручное подтверждение перед применением найденной стратегии.

**Готово, когда:** пользователь видит исходный лог, понятное резюме и может проверить каждую предлагаемую настройку до применения.

## Этап 5. Интерфейс и выпуск

**Цель:** отполированный Windows-интерфейс без декоративного шума.

- [ ] Привести навигацию, отступы, типографику и состояния элементов к единой Fluent-inspired системе.
- [ ] Добавить пустые состояния, подсказки и понятные сообщения об ошибках.
- [ ] Проверить масштабирование DPI, узкие окна и системную тему.
- [ ] Подготовить страницу релиза с номером версии, изменениями и известными ограничениями.
- [ ] Публиковать portable EXE только после успешной сборки и smoke-теста на Windows x64.

**Готово, когда:** основные сценарии проходят на чистой Windows x64, интерфейс не обрезается при масштабировании, релиз содержит понятные инструкции.

## Правила приоритета

1. Сначала исправления потери данных, зависаний, некорректной остановки и ошибок безопасности.
2. Затем сборка, тесты и воспроизводимость.
3. Затем сетевое поведение и совместимость.
4. В последнюю очередь — визуальные улучшения и новые удобства.

Новые функции не должны обходить существующие проверки и не должны менять пользовательские списки или конфигурацию без явного действия пользователя.
