# План развития Zapret2 Control Center

Основная платформа проекта — **C# / WPF / .NET 10**. Исходники приложения находятся в обычной структуре Visual Studio. Пункты отмечаются выполненными только после попадания кода в репозиторий и прохождения соответствующих проверок.

## Текущее состояние

- [x] Перенос базовой логики приложения на C# и разделение Core / App / Tests.
- [x] Интерфейс с разделами «Обзор», «Профили», «Диагностика» и «Настройки».
- [x] Поиск `winws2.exe`, `zapret-lib.lua` и `blockcheck2.cmd`.
- [x] Восемь встроенных примеров стратегий.
- [x] Создание, копирование, удаление и восстановление встроенных профилей.
- [x] Импорт аргументов из BAT/CMD с подстановкой `{BIN}` и `{LUA}`.
- [x] Импорт и экспорт профилей в JSON.
- [x] Резервная копия конфигурации и восстановление из `.bak`.
- [x] Запуск/остановка `winws2` с выводом stdout/stderr.
- [x] Диагностика других процессов `winws` / `winws2` с PID.
- [ ] Подтверждённая self-contained single-file публикация Windows x64 в CI.
- [ ] Успешная Windows CI-сборка C#-версии и проверка тестов.
- [ ] Smoke-тест на Windows 10/11 с реальным совместимым bundle.

## Этап 1. Надёжность приложения

- [x] Сохранять предыдущую конфигурацию перед записью новой.
- [x] Восстанавливать конфигурацию из резервной копии, если основной JSON повреждён.
- [x] Не перезаписывать существующие профили при импорте: конфликтующие имена получают суффикс.
- [ ] Проверить запуск, повторный запуск, остановку и аварийное завершение на реальном `winws2.exe`.
- [ ] Проверить поведение при отказе UAC, отсутствии Lua-файлов и занятом WinDivert.
- [ ] Добавить тесты граничных случаев импорта BAT/CMD и некорректных конфигураций.

**Критерий готовности:** корректное сохранение пользовательских данных, понятные ошибки и предсказуемый жизненный цикл процесса.
